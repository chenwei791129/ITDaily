# 消息來源內建於程式碼，由部署設定決定啟用哪些

「IT 新消息」要讓 fork 或貢獻者自行擴充來源。所有消息來源都和專案一起編譯進去，每個網站一個目錄（`src/news/sources/<網站>/`），部署時以 `NEWS_SOURCES`（逗號分隔的來源 id）和 `NEWS_LIMIT` 決定啟用哪些來源與顯示則數；未設定時使用程式碼裡的預設清單。
不做執行期動態載入的 plugin：Cloudflare Workers 只能執行整包 bundle，容器版若另做動態載入會讓兩種部署行為不一致。

## 考慮過的選項

- **只用程式碼註冊**（改註冊表後重新 build）：最少程式碼，但同一份映像無法在不同環境啟用不同來源。
- **程式碼內建、設定選用**（採用）：來源是編譯期的，選擇是執行期的；多一個小小的設定解析，兩種部署方式一致。
- **執行期載入外部套件**：Workers 做不到，否決。

## 影響

- `NEWS_SOURCES`、`NEWS_LIMIT` 是自架者看得到的契約，改名或改語意要視為 breaking change。
- 新增來源一律要進 repo（或 fork）並重新 build，沒有「不改程式碼就接新來源」的路。
- 設定錯誤（不存在的 id、非正整數的則數）直接視為部署錯誤：容器啟動失敗，Workers 的 `/api/news` 回 500。
